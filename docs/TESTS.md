# CandyIDE 测试清单（0.6.0）

本次随版本一起交付的新功能：**JS-apk 工程**（把 .subl 编译成 JS、注进内置模板 APK、手写 v1 签名、经 Shizuku 静默安装）。
请在设备上按下面的清单走一遍，有任何一项不符请直接告诉我。

## 一、本轮新功能：JS-apk 工程

| 步骤 | 期望结果 |
|------|----------|
| 工程页点「新建工程」→ 输入名字 → 选「JS-apk 工程」→ 创建 | 工程列表出现新卡片，类型标签为 **JS-apk 工程**（蓝色），直接进入编辑器，左侧有 hello.subl 与 jsapk.json |
| 编辑器顶栏多出一个 **🔨 打包 APK**（Primary 色）按钮，普通 JS 工程没有这个按钮 | 按钮可见，长按无异常 |
| 点「打包 APK」 | 日志页依次出现：`[打包] hello.subl 编译 → 注入模板 → 签名` → `[打包完成] app.apk 621 KB · 在工程 build/ 目录` → `[安装] Success` |
| 桌面找「Sublimation 应用」图标 | 出现新应用图标（蓝色三角） |
| 点开「Sublimation 应用」 | 白屏 + 逐行输出 `Hello, Sublimation!`、`42`、`7`，与应用内运行结果一致 |
| 再改 hello.subl（如 print 一句话）→ 保存 → 再打包 | 安装为覆盖更新，再次打开新内容生效 |
| 关掉 Shizuku 后再打包 | 日志出现 `[安装] Shizuku 不可用 … APK 已生成，可用文件管理器安装`，不再尝试静默安装 |

> 已知限制（v0 SDK）：所有 JS-apk 共用固定包名 `candy.jsapk.runtime`，装新应用会**覆盖**旧应用；内置同一把自签名证书（仅用于本地装机，不是正式发布签名）。

## 二、此前版本修复项回归

| 项 | 操作 | 期望 |
|------|------|------|
| 目录选中 → 新建 | 左抽屉点一个目录行（高亮），再点头部「新建」 | 新文件落到选中的目录里，提示行显示目标路径 |
| 切文件不闪退 | 打开多个文件反复点底部 Tab | 不崩溃（ScrollableTabRow indicator 已改 `indicator = {}`） |
| 抽屉遮罩关闭 | 打开文件树/输出抽屉，点遮罩空白处 | 抽屉关闭 |
| 顶栏不被状态栏盖住 | 打开输出抽屉看「输出/日志/诊断」页签 | 顶部留出状态栏高度 |
| 重命名走语言服务 | 编辑器里长按一个标识符 → 替换 | 报告改了几处；改完**自动落盘**（新增），不需再点保存；长按非标识符提示「只能对标识符重命名」 |
| 长按菜单点别处消失 | 长按出菜单后点空白 | 菜单消失，无残留 |
| 光标处诊断悬浮 | 代码里有语法错时把光标放到错误行 | 浮出诊断小提示 |
| 日志页超链接 | 日志页点诊断条目 | 跳到编辑器对应行列并关抽屉 |
| 编译失败标红、不跳输出 | 写个语法错再点运行 | 留在日志页，内容标红，不跳输出页 |
| 补全排序 | 输入 `sa` 看补全 | 符号排在关键字前面 |
| 自动缩进 | 行尾输入 `{` 回车 | 新行自动 4 空格缩进 |
| JS 平台工程运行 | demo 工程点运行 | 输出页出现 `Hello, Sublimation! 42 7` |

## 三、语言服务遗留问题（已知，非本次范围）

`renameFor`（重命名）在跨作用域多处引用时返回的编辑集合不完整——这是 sublimation 语言服务的缺陷，
IDE 的校验/对话框/应用编辑链路本身是通的；等语言服务修好 IDE 侧无需改动。
