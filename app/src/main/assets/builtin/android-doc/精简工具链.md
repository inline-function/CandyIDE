# 精简工具链：无 Gradle 构建 APK

目标：把安卓开发依赖从「完整 AndroidSDK（数 GB）+ Gradle」压缩成 **一个约 100MB 的
AndroidSDK for CandyIDE.zip**，只含 aapt2 / d8 / apksigner / zipalign / android.jar /
Kotlin 编译器（纯 Java）/ JRE。**Material Design 库保留**——靠 R 类合成填上 Gradle 缺位的活儿。

## 结论：可行，已验证

真机闭环：`.subl` → Sublimation 编译器（JVM jar）→ JS → `@postcompile` 钩子 →
`buildAndroidApk`（宿主函数）→ sdk-lite 构建脚本 → 签名对齐的 APK → `adb install -r` →
WebView 桥接运行。（计数器 demo：count 递增、静态视图存活、增量重组日志正常。）

## 一个 zip 装了什么

```
AndroidSDK for CandyIDE.zip (118MB)
├── bin/        aapt2.exe、zipalign.exe（x86_64；Termux 用 pkg 装的原生版）
├── lib/        android.jar 25.8MB、d8.jar 15.8MB、kotlin-compiler.jar 57.4MB、
│               apksigner.jar、kotlin-stdlib.jar、trove4j.jar
├── libs/       60 个 AndroidX/Material 依赖（版本钉死，来自 Gradle 缓存）
├── keystore/   debug.keystore（candydebug，统一签名便于覆盖安装）
└── build/      build-apk.ps1 / build-apk.sh / gen-r.py
```

对比：完整 SDK + Gradle 缓存约 10GB 级。

## 构建流水线（八步，无 Gradle）

1. 解压每个 AAR：取 `classes.jar` 与 `res/`
2. `aapt2 compile` 各资源目录（`--auto-add-overlay` 应对库间资源冲突）
3. `aapt2 link --manifest --java rgen -R … -o base.apk`
4. `gen-r.py`/构建脚本：把 R.java 转成 Kotlin R 类（见下）
5. `K2JVMCompiler`（编译器 jar 直接跑，`-no-stdlib`，classpath 全量）编译工程 Kotlin
6. `d8` 一把梭：应用类 + 全部库 jar → dex（minSdk 24，多 dex 自动）
7. dex + `assets/`（含 `app.js`）压入 base.apk
8. `zipalign` → `apksigner`（签名密钥随包）

## 关键难点：库 R 类的合成

Material/AppCompat 等库代码在**运行时** getstatic 自己包的 `R$attr`/`R$style`/`R$styleable`。
Gradle 世界里 AGP 会按最终资源表重写这些 R。无 Gradle 时必须自己补：

- `aapt2 link --java` 产出合并资源表的 R.java（应用包名下）
- 需求表（17 个包 × 类型）从 dex 反扫得到：
  `grep -aoE 'L[a-z0-9._/]+/R\$[a-z]+;' classes.dex | sort -u`
- 需求表内的包各发一个 Kotlin 文件：
  ```kotlin
  class R { class styleable { companion object {
    @JvmField val AppCompatTheme = intArrayOf(0x7f030001, …)   // styleable 数组
    const val AppCompatTheme_android_windowIsFloating = 0       // 样式索引
  } } }
  ```
  `class`+嵌套+`companion`+const val/@JvmField 的字节码形状与 Java R 一致，
  不需要 javac（JRE 即可）。styleable 数组值跨多行，解析器要缓冲到 `};`。

跳过这一步的症状：白屏，logcat 里 `Failed resolution of: Lcom/google/android/material/R$style;`。

## 平台差异

| 件 | Windows | Termux/Android |
|---|---|---|
| aapt2 / zipalign | bin/（x86_64 exe） | 随包携带的 aarch64 二进制：aapt2 取自 Termux 官方包（16.0.0.4），zipalign 取自 termux-zipalign（34.0.0）|
| 原生库 | — | `lib/native/`：aapt2 依赖的 protobuf/abseil/fmt/expat/png/z/libc++ 共 100 个 .so，经 `LD_LIBRARY_PATH` 加载 |
| d8 / apksigner / kotlinc | JRE 上跑，架构无关 | 同 |
| 运行依赖 | JRE | `pkg install openjdk-17 python zip unzip` |
| 本机安装 | adb（另一机） | Shizuku + `pm install`，或手机接 OTG 用自带 adb |

两种平台共用 `libs/`、`keystore/` 与 `build/gen-r.py`；脚本按平台选 `build-apk.ps1` 或 `build-apk.sh`。
Android 版打包结果即 `LiteASDK.zip`（见 `LiteASDK/README.md`）。

## 与编译器的对接（验收面）

`-A sdkDir=<zip 解压目录>` 指向工具包根；`ProcessorApi.buildAndroidApk` 不再调 gradlew，
改为运行 `build/build-apk.ps1`（Windows）/ `build-apk.sh`（sh），APK 直接落在 `-A outDir`。
工程切换签名后需卸载一次旧包；之后一律 `install -r`。

## 已知边界

- 库的清单合并（manifest merge）没做：appcompat/emoji2 的 provider/metadata 不并入——
  目前没用到自动初始化（startup/emoji2 未触发）；需要时再实现合并步骤。
- R 需求表随依赖版本钉死；换库要重扫 dex（README 里写了方法）。
- aapt2 高版本属性支持滞后（别用 SDK 36+ 新属性）。
