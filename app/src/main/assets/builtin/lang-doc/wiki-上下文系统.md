# 上下文系统与自动证明

把"断言"写进类型，交给编译器自动证明——这是凝华最核心的卖点。证明通过的代码才给编译，失败即编译错误。

> 本文对应根文档《上下文系统》《手动证明》。所有示例均以 v4 编译器（commit 802b43a，674 项测试全绿）逐条验证。

## 一句话原理

函数/结构体可以**携带命题**：

```subl
fun f(x: Nat)<x > 0>: Nat <$ >= 0> = x + 1
//            └── 上文（调用前必须满足）
//                              └── 下文（调用后保证成立，$ 指代返回值）
```

- **上文**：调用 `f` 前，编译器必须证明 `x > 0`。证不出 → `E-PRE-UNPROVEN`。
- **下文**：调用 `f` 后，编译器把 `f的返回值 >= 0` 注入后续上下文。
- 带空格的 `<` 是比较中缀（构成命题 `a < b`），紧贴标识符的 `<` 才是命题施加——二者靠空格消歧。

函数的完整签名是：

```subl
fun 函数名[理论参数](实际参数)<上文> : 返回类型<下文>
```

理论参数分**类型参数**（大写单字母，如 `T`）与**理论命题参数**（小写，如 `p`）。

## 伴生命题

每个函数除了"本体"和"调用返回值"，还有第三个身份——**伴生命题**：规定从伴生命题可以推出函数的下文。

| 对象 | 名称 | 作用 |
|------|------|------|
| `f` | 函数的本体 | 表达式，类型是函数类型 |
| `f(91, "abc")` | 函数的调用返回值 | 表达式，即返回值本身 |
| `f<91, "abc">` | 伴生命题 | 命题；规定 `f<…> → 下文` |

```subl
fun fact(): Null <answered> {
    unchecked.axiom[answered]          // 体内涵没再证，直接信任
}
// fact() 调用后，answered 弥散进作用域

fun usesFact()<answered>: Null {}       // 上文 answered 由弥散自动供给
```

## 命题参数与显式供给

带**理论命题参数**的函数叫"超越函数"，编译器无法自动推断，调用点要显式供给：

```subl
fun witness[@q]<q>: Null {}

witness<tagged<7>>()                    // 把命题 tagged<7> 供给给 @q
```

与之配套的是全称命题的自动实例化：若上下文里有 `forall n. tagged<n>`，需要 `tagged<7>` 时编译器自动合一供给。

## 自然命题

编译器自动注入的事实，你不需要手写：

| 触发 | 自动注入 |
|------|----------|
| `var n = 0` | `n : Nat`、`n = 0`、`n >= 0` |
| `n` 是 Nat 类型参数/字段 | `n >= 0` |
| 纯函数 `f` | `pure<f>` |
| 结构体实例 `var u = User(…)` | `u.字段 = 实参`、结构体伴生命题 |
| 数学记号区间 | `n ∈ (0..30)` 可推出 `n >= 0` |

```subl
fun demo(n: Nat, m: Nat): Null {
    ∴ n >= 0                          // 自然命题：Nat 参数自动有 n >= 0
    ∴ m >= 0
}
```

> 注意 `∧` 的结合力高于比较号：写合取命题请加括号，如 `(n >= 0) ∧ (m >= 0)`。

## 手动证明：因为-所以语句

需要明确"形式、前提、结论"时用**因为-所以语句**（根文档《手动证明》的复合形态）：

```subl
∵ ∀a. (a : Nat) -> (a >= 0),       // 形式：要调用的定理（全称命题）
  n : Nat                            // 前提：编译器先用自动证明验证
∴ n >= 0                             // 结论：证出后注入上下文
```

- `∵` 后第一个命题是**形式**，之后逗号分隔的都是**前提**；
- 前提证不出 → `E-PREMISE-UNPROVEN`；结论证不出 → `E-CANNOT-PROVE`；
- 该语句固定返回 `Null`（万物皆为表达式）。

简写：裸 `∴ q` 等价于 `∵ ⊤ ∴ q`（先证 q 再注入 q），保留兼容。

## 手动证明：四个专用语句

| 语句 | 语法 | 语义 |
|------|------|------|
| 非真即假 | `if[p] { … } else { … }` | 两支分别以 `p` / `¬p` 入上下文，证明**两支共同的结论**后注入 |
| 分类讨论 | `when[p ∨ q] { p => { … } q => { … } }` | 析取前提在 Γ 中；各支假设一个析取支，公共结论注入 |
| 存在引入 | `∃ x = t . P(x)` | 给出见证 `t`，证明替换后的性质 → 注入 `∃x. P(x)` |
| 策略调用 | `@策略名[命题]` | 调用命名证明器（如 `@simp`、`@subst`） |

```subl
@simp[(3 * 2 + 6) = 12]              // 化简器：自动证明器难证的算术交给它

if[n > 3] {
    ∴ n >= 4                        // 排中律：这支走 n > 3
} else {
    ∴ n <= 3                        // 这支走 ¬(n > 3)
}

unchecked.axiom[n = 3 ∨ n = 5]
when[n = 3 ∨ n = 5] {                // 分类讨论：两支都证出 n <= 5
    n = 3 => { ∴ n <= 5 }
    n = 5 => { ∴ n <= 5 }
}

∃ x = 1 . x = 1                      // 见证 1：证出 ∃x. x = 1
```

- `if[p]` / 经典推理需要先挂载经典逻辑：文件内任一声明标注 `@classic` 即挂载 `core.classic`（未挂载报 `E-NEED-CLASSIC`）。
- 分类讨论的析取前提必须已在 Γ 中，否则 `W-PROP-UNBOUND`；各支无公共结论报警告 `W-WHEN-NO-COMMON`。
- 存在语句的性质支持类型断言（`∃ x = 1 . x : Nat`）；与其它命题合取时（`∃ x = 1 . (x : Nat) ∧ (x > 0)`）由合取引入通道分解各成分分别证明，任一成分不成立即整体失败。

## 数学记号

源码直接写：`∈ ≥ ≤ ≠`、`∀ ∃`、`¬`（或 `!`）、`∧ ∨`、`→ ↔`、`⊤ ⊥`、`n ∈ (0..30)`。

```subl
unchecked.axiom[n ∈ (0..30)]         // 把区间事实注入 Γ（公理，见下方逃逸一节）
∴ n >= 0                             // 命中定理 rangeLowerBound
```

自定义命题用 `def`：

```subl
def =<a, b>                           // 声明谓词 = 接受两个项
def ≠<a, b> ↔ ¬<a = b>                // 带等价式的定义
```

## 定理函数 @theorem

标注 `@theorem` 的函数是**定理**：编译期擦除为 `Null`，供证明位（`∴` 合一/前件）使用。定理函数也可以作普通函数调用——值固定为 `Null`，在上下文推导中是空操作（不再禁止值级调用，旧文档里的 `E-THEOREM-VALUE-CALL` 诊断码已不存在）。

```subl
@theorem
fun leqRefl[a]: Null <a <= a>
```

- 只有 `@theorem` 显式标注的函数才进定理空间；
- 不同定理函数不能构造**同一形式**的全称命题（否则按重复定理报错）；
- 预置定理库（`core` 标准库，工程模式隐式挂载）：`core.logic`（等式自反/对称/传递、Leibniz 替换、MP、合取/析取/否定/量词、区间上下界、`<=` 自反与传递等）+ `core.classic`（排中律 `tertiumNonDatur`、双否消去、逆否，需 `@classic` 挂载）。

## 自动证明器能干什么

证明一个命题时，编译器按通道流水线依次尝试（命中即短路）：

1. **自定义命题展开**（按 `def` 定义展开后继续证）
2. **结构性目标分解**（合取引入：证 `A ∧ B` ⟺ 证 A 且证 B；`¬` / `→` 目标内层可判）
3. **常量原子真值**（`3 >= 0` 这类直接判定）
4. **常量类型判定**（字面量的 `e : T`）
5. **纯度结构相等**（不纯表达式不参与结构相等——连自反都不认）
6. **类型判定**（`x : Nat`，匹配注入的事实）
7. **常量归约**（`var s = 3 + 1` → 目标含 s 时归约为常量判定）
8. **线性算术**（整数域不等式/等式/区间的蕴含与析取反证；when 穷尽性受益）
9. **通用证明器**（饱和闭包：合取分解、∀ 实例化、前向 MP、modus tollens、矛盾检测，迭代至不动点）
10. **定理搜索**（定理空间 + 用户 `@theorem` 的后件结构合一，默认两跳）

通用证明器沿"**关键表达式**"工作：收集代码块中出现的一切表达式（优先内、其次外），用定理与策略（莱布尼茨替换、蕴含传播、自反、拆解定义）排列组合，命题中再出现的表达式只从关键表达式里收集，循环到超回合仍证不出即失败。

> 常见工程场景能做到**自动覆盖**；非线性算术、`∨/¬/→` 待证侧引入、`∃!` 唯一性、多名字量词不自动证——交给手动证明语句或策略，复杂到饱和报 `E-DEEP-SATURATION`（建议拆成小步）。

## 结构体伴生命题

结构体也能携带命题，构造时证明：

```subl
struct PosPoint(x: Nat, y: Nat)<x > 0, y > 0>

var p = PosPoint(1, 2)                // 自动证明 1 > 0 且 2 > 0 → 通过
// var q = PosPoint(0, 2)             // 证不出 0 > 0 → E-STRUCT-PROP-UNPROVEN
```

构造成功后，字段等式（`p.x = 1`、`p.y = 2`）与伴生命题自动注入上下文，结构体作为函数参数时同样供给给函数体。

## 逃逸：unchecked

两件事编译器办不到、但你负责时，用 `unchecked` 显式逃逸：

```subl
unchecked.axiom[forall n. tagged<n>]           // 注入公理（任意命题）
unchecked print(get7())                        // 放行单条语句的纯度/可变性检查
```

- `unchecked.axiom[p₁, p₂, …]` 把命题直接塞进 Γ；
- `unchecked <语句>` 包裹单条语句，绕过该语句的证明义务。

## 关键规则

- **上下文里的表达式必须是纯的**（证明系统不处理副作用）；不纯表达式的等式命题不承认，包括自反。
- 证不出 → 编译错误并列出尝试过的定理与当前 Γ；绝不悄悄放行。
- 可变变量与 `@ref` 变量的绑定等式不可靠，上下文系统对二者与不可变值一样采取"不注入"态度——证明命题时尽量用不可变值（见《副作用与可变性控制》）。
- 需要绕过时用 `unchecked`（显式逃逸，你对正确性负责）。

## 验证方法

本文示例的验证方式（单文件 check 不挂标准库，定理库需工程模式）：

```shell
java -jar build/libs/sublimation.jar check ctx.subl          # 纯 prelude 片段
java -jar build/libs/sublimation.jar compile <工程目录>      # 需 core/ 的定理库
java -jar build/libs/sublimation.jar explain E-CANNOT-PROVE  # 查诊断码含义
```
