# 脚本模式

> 本文档由 AI 起草，由我审定后修改。
> 定位：Sublimation 的嵌入式脚本运行时——宿主提供能力，脚本执行代码。
>
> 本文档是一份草案。

## 1. 定位

脚本模式**不是**"另一种编译模式"。它是**宿主-脚本运行时**，对应 Lua 嵌入 C、Python 嵌入 C++。

核心模型：

```
宿主（Kotlin）  →  注入能力（API + 类型 + 工程）  →  解释器  →  执行脚本
```

**脚本不找依赖，依赖由宿主给。** 脚本只有一个来源：**宿主预置的符号表**。

## 2. 与工程模式的差异

| 维度     | 工程模式               | 脚本模式           |
| -------- | ---------------------- | ------------------ |
| 入口     | `fun main()`，全局唯一 | 顶层语句，顺序执行 |
| 顶层     | 只能声明               | **可以有语句**     |
| 模块     | 目录即模块，有挂载     | **没有模块概念**   |
| 依赖来源 | 同模块文件 + 挂载      | **仅宿主预置**     |
| 执行     | 编译 → JS → node       | **解释器直接求值** |
| 产物     | JS 文件                | 无产物，直接执行   |

**脚本 = 一段代码 + 宿主给的能力。** 它不是工程，不参与模块系统。

## 3. 边界

### 在脚本里

- 语言核心：类型、命题、模式匹配、变量、函数、运算符
- 标准库：`List` / `Result` / `Optional` / 内建函数
- 宿主注入的 API、类型、注解

### 不在脚本里

- **模块系统**：无挂载、无跨模块引用、无 `.settings`
- **`@async` / `Task` / `Channel` / `Mutex`**
- **`fun main()`**：脚本顶层就是入口
- **工程级特性**：多文件、模块扫描、字典跨模块分发

## 4. 宿主 API

### 4.1 `@host` 机制

脚本可以调用宿主注入的函数。声明语法与 `@root` 同构：

```
@host fun hostLog(s: Str): Null
@host fun hostReadLine(): Str
```

- **`@root`**：声明签名，实现来自**编译器**（编译期内建）
- **`@host`**：声明签名，实现来自**宿主**（运行时注入）

两者在类型系统、诊断、调用点检查上完全一致。区别只是"谁提供实现"。

### 4.2 函数类型：ScriptFunction 统一接口

**跨边界的函数值统一为 `ScriptFunction`，不转成 Kotlin lambda。**

```kotlin
interface ScriptFunction {
    /** 泛型参数名，如 ["T"]；非泛型为空 */
    val typeParams: List<String>
    /** 上文（前置命题）——渲染后的字符串 */
    val preps: List<String>
    /** 下文（后置命题） */
    val posts: List<String>
    /** 形参类型（渲染），供宿主参考 */
    val paramTypes: List<String>
    /** 返回类型（渲染） */
    val retType: String
    /** 调用——实参按脚本值约定传入（见 §4.5） */
    fun call(args: List<Any?>): Any?
}
```

**泛型全部擦除为属性。** `[T](T) => T` 和 `(Nat) => Nat` 是同一个接口，区别只在 `typeParams` 的值。

**上下文（前后件）全部擦除为属性。** 宿主读到的是渲染后的字符串；实际检查在脚本侧进行。

**宿主调用 `f.call(args)` 时，解释器负责：**

1. 按实参推导/实例化泛型
2. 把宿主值包装成脚本值
3. 检查前件（走脚本证明器）
4. 求值函数体
5. 返回结果（包装回宿主值）

**宿主不需要理解泛型和上下文**——它只读属性、调 `call`。

**多态函数值的实例化时机：**

- 默认：`call` 时按实参实例化
- 可选：提供 `f.instantiate(listOf("Nat"))` 返回单态 `ScriptFunction`，供宿主多次调用

### 4.3 结构体：注入定义 + Map 传值

**不转换。宿主注入类型定义，用 Map 传值。**

```kotlin
// 注入类型定义
interp.injectStruct("Point",
    "x" to ScriptType("Nat"),
    "y" to ScriptType("Nat"))

// 注入带伴生命题的结构体（可选）
interp.injectStruct("Natural",
    "n" to ScriptType("Nat"),
    props = listOf("n > 0"))

// 注入带可变字段的结构体（可选）
interp.injectStruct("Counter",
    "value" to ScriptType("Nat"),
    mutableFields = listOf("value"))

// 注入带注解的结构体（可选）
interp.injectStruct("Point",
    "x" to ScriptType("Nat"),
    "y" to ScriptType("Nat"),
    annotations = listOf(Annotation("Serializable")))
```

**宿主构造值**——用 Map（或显式 `ScriptStruct`）：

```kotlin
interp.register("getPoint") { _ -> mapOf("x" to 1L, "y" to 2L) }
```

脚本侧：

```
var p = getPoint()
print(p.x)     // 1
print(p.y)     // 2
```

**脚本完全感知不到"这是宿主来的"**——它看起来就是一个普通 `Point` 值。

**`ScriptType` 需支持完整类型语法**：Named、List、Optional、Tuple、Function。嵌套结构体（如 `List[Point]`）通过它表达。

**依赖顺序由宿主负责**——`injectStruct` 不自动拓扑排序。

### 4.4 注解：通用化

**所有节点统一带 `annotations` 属性。** 注解是通用容器，不专门设计。

```kotlin
data class Annotation(
    val name: String,                    // "mut" / "impure" / "MyCheck"
    val args: List<Any?> = emptyList()   // 常量或类型引用
)
```

**所有 AST 节点**（`StructDecl` / `FunDecl` / `VarStmt` / `Param` / `ClassDecl` / `EnumDecl` …）加 `annotations: List<Annotation>`。

**内置注解**是编译器额外认识的名字：

| 注解       | 挂在哪              | 编译器行为                      |
| ---------- | ------------------- | ------------------------------- |
| `@mut`     | var / param / field | 可变性检查                      |
| `@impure`  | fun                 | 纯度检查                        |
| `@root`    | fun                 | 内建白名单检查                  |
| `@host`    | fun                 | 宿主 API 检查                   |
| `@theorem` | fun                 | 登记定理                        |
| `@classic` | decl                | 挂载 core.classic               |
| `@async`   | fun                 | 异步传染（脚本中不生效，见 §5） |

**用户自定义注解**（如 `@MyCheck`）：编译器不认识 → 透传 → 注解处理器读。

**注解参数**：**常量 + 类型引用**，不支持任意表达式。

```kotlin
Annotation("Deprecated", listOf("msg"))
Annotation("Target", listOf(ScriptType.Named("Point")))
```

**用户不能自定义注解名**——注解的名字空间由宿主提供，用户只使用。

**`@Target` 限定**（可选）：第一版不做。注解可挂任何位置，处理器自行判断。

### 4.5 注册接口（Kotlin 侧）

```kotlin
val interp = Interpreter()

// 注册宿主函数
interp.register("hostLog") { args -> println(args[0]); null }
interp.register("hostReadLine") { _ -> readLine() ?: "" }

// 注入结构体类型
interp.injectStruct("Point",
    "x" to ScriptType("Nat"),
    "y" to ScriptType("Nat"))

// 注入工程能力（可选）
interp.register("loadProject") { args -> loadProject(args[0] as String) }
interp.register("processAnnotations") { _ -> processAnnotations() }

// 执行脚本
interp.run(scriptSource)
```

### 4.6 类型映射

| 脚本类型              | 宿主值（Kotlin）           |
| --------------------- | -------------------------- |
| `Nat` / `Int` / `Rat` | `Long` / `Long` / `Double` |
| `Str`                 | `String`                   |
| `Bool`                | `Boolean`                  |
| `Null`                | `null`                     |
| `List[T]`             | `List<T>`                  |
| `Optional[T]`         | `Optional<T>`              |
| `Result[T, E]`        | 自定义 `sealed class`      |

**值跨边界一律引用语义**（非拷贝）。脚本改宿主对象 = 改宿主对象。

## 5. 特性对照

脚本移除**所有异步特性**——脚本是同步解释，异步引入挂起-恢复语义，与线性执行模型冲突。

## 6. 执行模型

```
解释器启动
  → 加载标准库（语言自带）
  → 加载宿主 API（宿主注入）
  → 加载结构体定义（宿主注入）
  → 加载脚本（用户写的）
  → 逐条执行顶层语句
```

**顶层语句的作用域**：

- 顶层 `var` 对后续顶层语句可见
- 顶层 `fun` 对脚本内所有语句可见
- **声明不对外可见**——脚本结束，作用域消失

**错误处理**：执行到一半报错 → **前面已执行的效果保留**（同 Python）。

- 类型类字典不跨边界——宿主 API 签名不用类型类约束
- 泛型擦除——宿主只读属性、不做静态对齐
- 上下文（前后件）擦除——检查在脚本侧，宿主看不见证明过程

**这个原则是对的。** 它把宿主的心智负担压到最小：**宿主只需要理解三种通用表示**。

## 7. 与工程的关系

**脚本独立于工程，但宿主可以注入"工程能力"。**

典型用法——**脚本操作注解处理器**：

```
// 脚本侧
@host fun loadProject(path: Str): Null
@host fun processAnnotations(): Null
@host fun writeGenerated(path: Str): Null

loadProject("myproject/")
processAnnotations()
writeGenerated("out.subl")
```

**脚本不自带工程，但宿主可以给它工程。** 与宿主-脚本模型一致——一切能力来自宿主。
