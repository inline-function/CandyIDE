# 激进证明模式

编译器默认的自动证明是**有界搜索**：闭包轮数、证明深度都有封顶——快，绝大多数日常命题够用，但链长了或者要用经典逻辑工具时就证不出，只报 `E-CANNOT-PROVE`。

`--prover=aggressive` 把这些上限拆掉：

- 饱和层改成**不动点判停**（没有轮数截断），一直推到推不动为止；
- 目标层改成**迭代加深**（预算翻倍），深度截断会重试而不是直接放弃；
- 多出三个经典逻辑工具：排中律前向实例化、∨ 消去、反证法（都只对挂了 `@classic` 的文件提供）；
- ∀ 实例化从「表达式一维」扩成**表达式 / 类型 / 命题三维**候选池。

代价：可能很慢，甚至**不停机**（这设计中的一部分，见下）。所以它是**选择性开关**而非默认。

> 设计文档：`idea doc/激进模式.md`。本文片段均用 `build/libs/sublimation.jar` 实测通过。

## 健全性底线（先立规矩）

激进模式只加搜索预算与经典规则，**不猜**：

- 不引入 Γ 里没有的新项——实例化的候选全来自当前命题里的表达式/类型/命题本身；
- 不降公理强度——它不会把 `unchecked.axiom` 之外的东西当公理；
- 经典工具（排中律、反证）只在文件挂了 `@classic`（即声明 `core.classic` 语义）时启用；没挂就是直觉主义，`¬¬p → p` 都不会给你推；
- 普通模式（默认）逐字节不变——同一份代码不加旗标，诊断输出与之前完全一样。

## 打开方式

`compile` / `check` 加旗标（`run-script` 不受影响——脚本模式不做命题证明）:

```bat
java -jar sublimation.jar compile MY_PROJECT --prover=aggressive
```

可观测性旗标：

| 旗标 | 作用 |
|---|---|
| `--prover=aggressive` | 开启激进模式（全有全无，没有中间档） |
| `--prove-verbose` | 提高进度输出频率 |
| `--prove-interval=2s` | 进度节流间隔（默认 5 秒；支持 `500ms` / `2s` / `1m`） |
| `--prove-dump=路径.md` | 中断时诊断报告路径（默认 `sublimation-prover-dump.md`） |

进度走 **stderr**（标准输出仍是干净的 JS），形如：

```
[激进证明] 已证 12 / 待证 3 | 搜索中 ... 池规模 expr=47 type=12 prop=31
```

中断（**Ctrl-C**）时把当前证明栈（卡住的目标、Γ、已试定理）写进报告文件，退出码 **130**：

```bat
[激进证明] 已中断——诊断报告写入 sublimation-prover-dump.md
```

## 什么变得更可证了

### 析取三段论：∨ 消去

```subl
fun disjSyl[a, b]<a ∨ b, ¬a>: Null {
  ∴ b
}
```

普通模式：`b` 不是任何蕴含的后件，回溯够不着，证不出。激进模式把 `a ∨ b` 拆开：`a` 支与 `¬a` 矛盾（爆炸），`b` 支直接命中——两支都成，`b` 成立。

### 排中律前向实例化

```subl
@theorem fun LEM[p]: Null <p ∨ ¬p>

@classic
fun lemCase[p, q]<p -> q, ¬p -> q>: Null {
  ∴ q
}
```

Γ 里既没有 `p` 也没有 `¬p`，普通模式没有任何出发点。激进模式把 LEM 形态的定理（这里是文件里自带的 `LEM`，挂载 `core.classic` 后还有 `tertiumNonDatur`）对命题池里每个候选实例化一遍，注入 `p ∨ ¬p`，然后 ∨ 消去：`p` 支经 `p -> q` 得 `q`，`¬p` 支经 `¬p -> q` 得 `q`。

### 反证法

```subl
@classic
fun raaCase[p, q]<¬p -> q, ¬p -> ¬q>: Null {
  ∴ p
}
```

假设 `¬p`：两支导出 `q` 与 `¬q`，矛盾——所以 `¬¬p`，经典地得 `p`。**不挂 `@classic` 时这条通道是关的**（直觉主义只给 `¬¬p`，不给 `p`）。

### 命题维的 ∀ 实例化

```subl
@classic
fun propInst[r]: Null {
  unchecked.axiom[∀p. p ∨ ¬p]
  ∴ r ∨ ¬r
}
```

`∀p` 的 `p` 是**命题变量**（不是表达式）。普通模式的实例化候选只有 Γ 里的表达式项，对命题变量不可实例化。激进模式按维度分派：`p` 出现在命题位置 → 用命题池里的 `r` 实例化，得到 `r ∨ ¬r`。

## 激进模式也不会猜

加了预算不等于放宽健全性。证不出的命题照样报 `E-CANNOT-PROVE`——诚实、和普通模式同一个错（`show/激进模式/大搜索.subl` 就是这样的例子：20 个析取前件，普通与激进都证不出单个 `p20`，因为析取链本来就不蕴含它）。

## 不停机是设计的一部分

激进模式可能**一直搜索下去**（不动点不可达 / 深度预算一直翻倍）。这不是 bug：默认模式的存在就是为了给「要确定性的人」，激进模式是给「宁可等也要试一试的人」。

- 进度行让你看到它还活着、在干什么；
- **Ctrl-C** 中断：把当前证明栈（卡在第几个目标、Γ 是什么、已试过哪些定理）写进 `sublimation-prover-dump.md`（或 `--prove-dump` 指定路径），退出码 **130**；
- 诊断报告里通常能一眼看出是命题太难、还是目标根本不可证（比如 `¬(∀n. P(n))` 这类需要反例的目标——反例模型构造在第二波）。

## 实测对照（show/激进模式/）

四个示例在两种模式下的结果（`java -jar build/libs/sublimation.jar compile <file> [--prover=aggressive]`）：

| 示例 | 普通模式 | 激进模式 |
|---|---|---|
| 析取三段论.subl | `E-CANNOT-PROVE …结论 b 证不出` | 编译出 JS ✓ |
| 排中律.subl | `E-CANNOT-PROVE …结论 q 证不出` | 编译出 JS ✓ |
| 反证法.subl | `E-CANNOT-PROVE …结论 p 证不出` | 编译出 JS ✓ |
| 命题维实例化.subl | `E-CANNOT-PROVE …结论 r ∨ ¬r 证不出` | 编译出 JS ✓ |
| 大搜索.subl | `E-CANNOT-PROVE` | `E-CANNOT-PROVE`（不猜，同一错） |

## 适用与不适用

适合：证明链很长（跨多步 `+前提` 推演）、需要分情况、目标本身可证但普通预算不够。

不适合：需要**构造反例**来证伪的目标（如「不是所有 n 都满足 P」）——那需要反例模型搜索，激进模式第一波不做；以及 CI 等要求确定耗时的场合（它会一直试到证出或你打断）。
