# 手动证明

> 此前关于手动证明的特性出现了诸多的混淆，如今重新定义相关语法语义。本文档规定了**因为-所以语句**、**非真即假语句**、**分类讨论语句**、**存在语句**的含义，并且简单介绍如何使用**策略**驱使策略证明器去证明核心自动证明器无法自动证明的命题。
>
> 本文档是根文档，AI不得擅自修改，否则让你飞起来。

## 定理

某些定理涉及类型或者命题参数，编译器在正常模式下无法对其自动调用。

这个时候就需要手动调用定理，比方说排中律：

```
`law of excluded middle`[p] //p ∨ ¬<p>
```

观察这个函数

```
@theorem
fun `law of excluded middle`[p]: Null <p ∨ ¬<p>>
```

它的`@theorem`表示它是**定理函数**，没有副作用，返回值固定为Null，编译时会被擦除。不同名称的定理函数不能构造同一形式的全称量词命题，否则报错，因为定理函数本质上就是一个全称量词命题，不依靠名字。

以前说过，函数的构造本身带来一个自然的全称量词命题，比方说排中律的就是：

```
∀@p.`law of excluded middle`<p>
```

``law of excluded middle`<p>`是排中律的伴生命题，有：

```
∀@p.`law of excluded middle`<p> → (p ∨ ¬<p>)
```

组合上面两个定理，我们可以得出：

```
∀@p.p ∨ ¬<p>
```

由此我们推广，函数的参数列表就是它自然全称量词命题的主语，函数的伴生命题就是它自然全称量词命题的谓语。

## 因为-所以语句

有时候不想自己去搜索定理的名字，或者定理名非常长不想写（如上面的排中律），只希望通过给定的形式、前提、结论去表示调用定理，这在中学数学非常常见，就是**因为-所以语句**。

因为-所以语句的格式如下：

```
∵ ∀a b.(a : Rat ∧ b : Rat) → ((a + b) = (b + a)),
  a : Rat,b : Rat
∴ (a + b) = (b + a)
```

这里给定了:

+ 形式(`∀a b.(a : Rat ∧ b : Rat) → ((a + b) = (b + a))`)

+ 前提(`a : Rat ∧ b : Rat`)

+ 结论(`(a + b) = (b + a)`)

首先编译器从符号表中查找有没有一个构造了上述形式的定理函数，于是它找到了:

```
@theorem
fun `commutative law of addition`(a : Rat,b : Rat) : <(a + b) = (b + a)>
```

（这个定理的定义也可以写成这样）：

```
@theorem
fun `commutative law of addition`(a,b) : <(a : Rat ∧ b : Rat) → (a + b) = (b + a)>
```

注意到这个函数构造了自然命题`∀a b.(a : Rat ∧ b : Rat) → ((a + b) = (b + a))`，编译器就认为这是用户想要调用的定理。

如果一个全称量词命题的谓词是一个蕴含命题，那么称呼这个蕴含命题的前件为命题的前提，后件为命题的结论。

`∵`部分的第一个命题是命题的形式，之后的命题是前提，编译器会去验证前提是否成立。

比方说上述例子有`a : Nat`和`b : Nat`，尽管你目前正在手动证明，但是编译器也会帮你使用自动证明验证前提是否成立，如果不能自动证明，那么请你自己去证明哦。这里编译器就帮你证明了`a : Rat`和`b : Rat`。

找到了命题，确认了前提，编译器会判断`∴`部分的命题是否是这个定理的后件。

最后，如果一切没有问题，这个`∵xxx∴p`的语句会给出`p`证明。尽管我们说它是语句，但是因为我们的语言哲学----**万物皆为表达式**，因此因为-所以语句是一个固定返回Null的表达式。

## 非真即假语句

在经典逻辑中，命题是非真即假的。通过把if的圆括号换成方括号，表示一个非真即假语句：

```
if[n < 0]{
    // n < 0
    ∵ ∀n.(n : Nat) → (n ≥ 0),
      n : Nat
    ∴ n ≥ 0
    ∵ ∀n m.(n : Rat ∧ m : Rat) → (n ≥ m ↔ ¬<n < m>),
      n : Rat,0 : Rat
    ∴ ¬<n < 0>
    ∵ ∀@p.(p ∧ ¬<p>) → ⊥,
      n < 0,¬<n < 0>
    ∴ ⊥
    // 从矛盾可以证明出所有命题，自然包含¬<n < 0>
}else{
    // ¬<n < 0>
}
// ¬<n < 0>
```

在语句内部，分别赋予了两个相反的命题。语句会证明两个部分共同有的命题。

上述例子，两个分支都证明了`¬<n < 0>`，于是这个非真即假语句就证明了`¬<n < 0>`。

如果没有共同命题，编译器报警告。

因为设计哲学的问题，这个语句固定返回Null。

## 分类讨论语句

析取式总是有一个命题成立，通过对析取式进行分类讨论，得出无论哪个分支，都可以证明出某命题。通过把when换成方括号，表示一个分类讨论语句。

```
when[n > 0 ∨ n < 0] {
    n > 0 => {
        ∵ ∀n m.(n : Rat ∧ m : Rat ∧ n > m) → (n ≠ 0),
          n : Rat,0 : Rat,n > 0
        ∴ n ≠ 0
    }
    n < 0 => {
        ∵ ∀n m.(n : Rat ∧ m : Rat ∧ n < m) → (n ≠ 0),
          n : Rat,0 : Rat,n < 0
        ∴ n ≠ 0
    }
}
// n ≠ 0
```

上述分支中，无论哪个部分成立，都可以证明出`n ≠ 0`，故分类讨论语句证明`n ≠ 0`。

如果没有共同命题，编译器报警告。

因为设计哲学的问题，这个语句固定返回Null。

## 存在语句

声明函数以构造一个全称量词，而使用存在语句构造一个存在量词。

```
∃n = 0. n : Nat ∧ n = 0
```

这个语句证明了

```
∃n. n : Nat ∧ n = 0
```

因为设计哲学问题，这个语句返回Null。

## 策略

证明器是一个一个默认不启用的模块，由编译器或者注解处理器提供，它们给出策略，当遭遇以下情况的交集，你可以使用策略。调用策略的格式是`@策略名[命题]`

比方说证明`(3 * 2 + 6) = 12`，自动证明器只涉及对表达式和定理的排列组合，难以证明这种算术问题。这个时候可以使用化简器去证明这个命题。

```
@simp[(3 * 2 + 6) = 12]
```

这个时候编译器会调用化简证明器去证明这个命题。

因为语言哲学，所有的策略语句都会返回Null。
